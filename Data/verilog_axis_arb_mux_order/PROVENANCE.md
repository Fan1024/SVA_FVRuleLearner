# verilog_axis_arb_mux_order provenance

assembled: 2026-08-19

source: an earlier internal task package
        (copied out of; the source tree was not modified)

upstream RTL: verilog-axis @ 48ff7a7e2ef782cf778d47910cf85835c64b1bce
              (alexforencich), `rtl/{priority_encoder,arbiter,axis_fifo,
              axis_arb_mux}.v`, byte-for-byte per the source's DERIVATION.json.

Four AXI-Stream sources each feed an 8-deep `axis_fifo`; a locked round-robin
`axis_arb_mux` merges them into one 16-deep output `axis_fifo`. Every fourth
accepted beat on a source is marked `tlast`, so each source emits fixed 4-beat
frames. Four independent reference rings (one per source, 64 entries) record
what was pushed, and the target checks the output stream against them: payload
order per source, frame boundary, source ownership via the mux's own `tid`, and
non-interleaving of frames at the output.

top: testbench
environment: lists/diag_verilog_axis_arb_mux_order.tcl
             (task `diag_verilog_axis_arb_mux_order`; declares no assumptions
             of its own -- the package's five live in `ft/tb.sv`)
target: T_ARB_MUX_FRAME_ORDER  (testbench.T_ARB_MUX_FRAME_ORDER)

The source's `DERIVATION.json` also lists five covers -- `C_INPUT_BACKLOG`,
`C_FOUR_WAY_CONTENTION`, `C_OUTPUT_BACKLOG`, `C_ALL_SOURCES_OUTPUT`,
`C_REFERENCE_WRAP` -- and five assumptions -- `A_RESET_IDLE`,
`A_IN{0,1,2,3}_STICKY`. All ten elaborate with the package. The covers are what
`COVER_DEPTH` counts if a round is given `--cover-s`; they are not targets.

Parameters, from the source's `DERIVATION.json`: `data_width=8`,
`sources=4`, `fixed_frame_beats=4`, `input_fifo_depth=8`,
`output_fifo_depth=16`, `reference_depth_per_source=64`.

## Only one file is analyzed, on purpose

`lists/tc_elab.files` lists `+incdir+rtl` and `ft/tb.sv`, and nothing else. The
four RTL files are pulled in by `` `include `` at the top of `ft/tb.sv`, which
is how the source's `tcl/setup.tcl` reaches them too. Listing them as well
would declare every module twice under `--single-unit`. `+incdir+rtl` is what
makes the includes resolve, and it is the one thing in the list that is not a
source line -- the round's appended `../submission/<worker>.sv` lines stay
source lines at the end, as they must.

## What changed from the source's tcl/setup.tcl, and why

Kept: `clear -all`, `analyze -sv12` with `+incdir+rtl`, `elaborate -top
testbench -disable_auto_bbox`, `set_clock_reference_mode auto`, `clock clock`,
`set_cumulative_reset on`, `reset -expression {reset == 1'b1}
-max_iterations 100`.

Dropped, with reasons:

- **`FROZEN_INPUT_MISSING`**, the existence check over the frozen input set. It
  requires `submission/helpers.sv` to exist before elaboration; v5 stages one
  standalone file per worker under a different name.
- **The name censuses** (`fls_require_exact_names` over
  `FLS_BASE_ASSERTIONS` + `FLS_HELPER_PROPERTIES`, and over
  `FLS_BASE_ASSUMPTIONS`). They demand the elaborated property set equal a list
  computed by a Python front end that v5 does not run. v5 stages a different
  helper set every round, so an exact-match census rejects every legal round.
  Not lost: `cex.tcl` runs `LABEL_INDEX`, `CHECK_FT_MODULES` and
  `CHECK_LABEL_COLLISIONS` after this file.
- **`TARGET_RESOLUTION_FAIL` / `HELPER_RESOLUTION_FAIL`.** Same reason. The
  target census survives in the diag as a printed count that fails only on
  zero.
- **`MULTI_DRIVEN` as an error.** Now reported as
  `MULTIPLE_DRIVEN count=... list=...`. An abort here kills the round before
  any verdict; the number in the log answers the same question.
- **`+define+FLS_EVALUATION` and `+incdir+<submission>`.** See the scrub below.
- **The whole of `tcl/evaluate.tcl`.** That is the source's own property ledger
  and proof policy. v5 brings its own (`v5/grid.tcl`, `CONFIG_GRID`) and writes
  its own report.

Added, not in the source: `AFRA_ELAB_EXTRA` handling (the payload exports it
unconditionally and a recipe that ignores it drops the run's elaborate switches
silently), `set_elab_time_limit`, `compilation -profile`, `task -create FPV`,
and the proofgrid profile load.

Deliberately NOT added: `-create_related_covers` / `-witness_cover_property`.
The source task elaborates without them, and they would attach
precondition/witness covers to every helper an agent writes, changing what the
cover phase counts.

## Scrubbed

`ft/tb.sv`, two hunks. Nothing else in the package was edited.

- **3 lines deleted** at the end of the module:

        `ifdef FLS_EVALUATION
        `include "helpers.sv"
        `endif

  Not a leak -- an incompatibility, and the same one `openpiton_pmesh_order`
  removed. In the source flow a submission is one `helpers.sv` textually
  included INSIDE `module testbench`. v5 stages one bound standalone file per
  worker and `v5/elab.tcl` fails a worker whose file does not bind under its
  own module name. Left in, the directive is either inert (no
  `FLS_EVALUATION`) or fatal (no such file), and it would tell an agent to
  write in a shape the harness rejects. This is why the `placement` string for
  this task is the standalone/`bind` one.

- **3 lines added** between the includes and `` `default_nettype none ``:

        // Restored after the includes: every verilog-axis file ends with
        // `resetall, which clears the `timescale they set at their top.
        `timescale 1ns / 1ps

  Every one of the four verilog-axis files opens with `` `resetall ``,
  `` `timescale 1ns / 1ps ``, `` `default_nettype none `` and closes with
  `` `resetall ``. The closing `` `resetall `` clears the time scale, so
  `module testbench` -- declared after the includes -- has none while the four
  RTL modules do. Slang rejects that outright:

        ft/tb.sv:8:8: error: design element does not have a time scale defined
                             but others in the design do

  and `v6_dataset/elab_local.py` is the gate. The fix has to live in the source
  rather than in the file list, because that list is fed to BOTH Jasper's
  `analyze -f` and Slang's `-f`, and `--timescale` is a Slang-only option that
  Jasper would reject. Restoring the RTL's own `1ns / 1ps` is inert for FPV --
  a time scale affects delays and `$time`, and this package has neither -- and
  it carries forward through the single compilation unit to the worker files
  the round appends, which have no time scale of their own either.

Nothing else was removed. In particular the source's own header comments and
the reference-model structure are kept: the task's statement of what it built
is the task, and the reference queues are load-bearing code.

## DESIGN_KEEP: this task needs a non-empty one

The target's instrument is registered, exactly as `openpiton_pmesh_order`'s is.
`target_ok` is combinational, but every term it reads is checker state held in
`always @(posedge clock)` registers at the top level:

    ref_count[0..3]        the per-source occupancy the target compares against
    ref_rptr[0..3]         where in the ring the next output beat must match
    ref_wptr[0..3]         where the next push lands (and so what rptr chases)
    output_frame_active    is a frame in progress at the output
    output_frame_source    which source owns it

Under `ENTER_FRA_KEEP` every register not matched by a keep pattern starts
arbitrary. Cut, `ref_rptr` points at an arbitrary ring entry and
`output_frame_source` names an arbitrary owner, so `T_ARB_MUX_FRAME_ORDER` is
falsified at cycle 0 for a reason that is not the design's and that nothing in
the design can correct.

The patterns reported for `taskdefs.DESIGN_KEEP`, from `taskdef.json`, are

    ref_(wptr|rptr|count)
    output_frame_(active|source)

matched unanchored with Tcl `regexp` against instance paths as
`get_design_info -list register` returns them (`testbench.ref_wptr`, ...),
which is the form `_CHECKER_KEEP` uses. Checked against the elaborated design:
no module in `rtl/` declares any name containing `ref_` or `output_frame_`, so
neither pattern reaches design state. The two FIFOs, the arbiter and the mux
all stay cut.

### The rings' storage is unreset, and the keep set is pointers only

`ref_data` and `ref_last` are deliberately NOT in the patterns, for the same
reason `openpiton_pmesh_order` leaves `ref_mem` out. The reset branch of
`ft/tb.sv` assigns `frame_pos`, `ref_wptr`, `ref_rptr` and `ref_count` and
nothing else; `ref_data`/`ref_last` are written only on a push. So they have no
reset value at all, and `stopat -reset` cuts a reset value -- keeping a
register that has none is a no-op. Those 4 x 64 x 9 = 2304 bits start arbitrary
either way, and matching them would only inflate the `KEEP_PATTERN design`
count in the round log, which is read as a measurement.

So the kept state is exactly

    ref_wptr    4 x 6 bits
    ref_rptr    4 x 6 bits
    ref_count   4 x 7 bits
    output_frame_active   1 bit
    output_frame_source   2 bits   = 79 bits

and the instrument is anchored at its POINTERS, not at its memory. "A read
entry was written" is therefore a property that has to hold, not something the
keep set establishes: `target_ok` requires `ref_count[src] != 0` before it
reads `ref_data[src][ref_rptr[src]]`, and a count only becomes non-zero through
a push, which is the same event that writes `ref_data` at `ref_wptr`.

Left cut deliberately:

- `frame_pos` -- stimulus, not instrument. It drives `input_last`, which goes
  to the design FIFO's `s_axis_tlast` and to `ref_last` in the same cycle, so
  an arbitrary start moves the first frame boundary and cannot disagree with
  itself.
- `past_valid` -- it only gates the four `A_IN*_STICKY` assumptions. Arbitrary
  either way it changes the assumption set, and an assumption cannot falsify a
  target.
- `seen_sources`, `seen_wrap` -- read by covers only, never by `target_ok`.

All five kept families are reset-assigned, so the patterns cannot match zero
and cannot trip `cex.tcl`'s "design keep pattern matched nothing" FAIL. Expect
14 hits if Jasper lists array elements individually, 5 if it lists arrays.

## Known caveat: the target is an immediate assertion, so `derive_targets` cannot locate it

`taskdefs.derive_targets` looks for a line that starts with `<label>:` and
contains the literal `assert property`. This package's target does not have
that shape -- it is an immediate assertion inside the checker's clocked always
block:

    T_ARB_MUX_FRAME_ORDER: assert (target_ok);

so `derive_targets` returns `source: ""`, `line: 0` and the model phase renders

    - `T_ARB_MUX_FRAME_ORDER` — not located in the mounted sources

instead of a file and line. Nothing else is affected: `v5/round.py` reads
`TASKS[task]["target_labels"]` and `cex.tcl:LABEL_INDEX` keys on the last
dot-separated component, so `T_ARB_MUX_FRAME_ORDER` resolves in a round, and
the diag census finds it by name. The cost is that a model-phase agent is told
the target's name but not where to read it.

This is not fixable inside the package without rewriting the source's target
into a concurrent assertion, which would change what the task measures. The fix
is in `taskdefs.TARGET_PATTERN`, which this port was told not to touch. It
applies identically to the other four packages in this group -- all five state
their target as an immediate assertion.

### Not verified, and what is uncertain

Jasper has NOT been run: no proof, no cover reachability. Slang elaboration is
all that has been checked. The assertions whose truth is a judgement rather
than a reading:

- `T_FAIR_SOURCE_SERVED_WITHIN_TIGHT_N` (16) is the exact round-robin argument
  -- three other four-beat frames plus the frame in progress. If the argument
  is off by a beat this is a cex and `..._LOOSE_N` (24) is the survivor. Both
  are shipped on purpose.
- `T_CONSERV_STAGE1_OCC_MATCHES_FIFO_STATE` and
  `T_CONSERV_STAGE2_OCC_MATCHES_OUTPUT_FIFO_STATE` add up `axis_fifo`'s memory,
  read pipeline, skid FIFO and output register by hand. A term missed is a cex.
- `T_BOUND_INPUT_SKID_FIFO_NEVER_FULL` / `T_BOUND_OUTPUT_SKID_FIFO_NEVER_FULL`
  rest on `pipe_ready = !out_fifo_half_full_reg` capping the skid at 4 plus the
  two pipeline stages; the bound shipped is 7, the analysis says 6.
- The three bounded-response/deadlock counters are guarded on the GRANTED
  source having data. Unguarded they are false: this arbiter holds a grant
  until `tlast`, so a source that stops mid-frame starves the others for as
  long as it likes, and that is the design's, not the assertion's, behaviour.
