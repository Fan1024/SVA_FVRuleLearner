The whole SERV RISC-V core runs against the riscv-formal RVFI instruction
model for **ADDI**. `sva/insn_addi.v` is the generated I-type spec; the SERV
core's `serv_debug` block emits the RVFI channel; `sva/rvfi_insn_check.sv`
compares the two on every retirement the spec claims.

         (`testbench.checker_inst.*`, sva/rvfi_insn_check.sv)

## This is a small flat design, and that is the point

The elaborated hierarchy is **19 instances** and about **215 registers**, of
which 115 are in `serv_debug` (the RVFI emitter, on at `DEBUG=1'b1`) and 52 in
`serv_decode`. `hierarchy.build` cuts it into **13 regions**. A the internal reference task task
has 6,644 instances. Nothing is wrong: SERV is a bit-serial core that fits in
a few hundred flops, and eight of these packages differ only in which rvfi
check is instantiated. Region counts in the single digits to low teens are the
expected shape for this family and should not be read as a broken port.

## Where the recipe came from — there was no `tcl/` to derive it from

The source package ships **`engine/ric3.toml`**, not a Jasper script: a config
for the **rIC3** model checker with a **yosys-slang** front end (rIC3 commit
`28441a52`, yosys `8101c87f`, yosys-slang `7e05094a`). `engine/` was NOT copied
— it is the source's own engine policy, the same role `tcl/` plays in the
OpenPiton packages, and this harness brings its own. Everything in it that is a
fact about the task rather than about rIC3 was carried into `lists/`:

    ric3.toml `dut.files`     -> the file list in lists/tc_elab.files, same order
    ric3.toml `include_files` -> `+incdir+ft`, and `ft/defines.sv` listed FIRST
    ric3.toml `top`           -> `elaborate -top testbench`, taskdef.json `top`
    ric3.toml `reset`         -> `reset -expression {reset == 1'b1}`
    `parser = "yosys_slang"`  -> `analyze -sv12` for the whole list

`lists/tc_elab.tcl` is otherwise this repo's own convention, taken from
`tasks/openpiton_pmesh_order/lists/tc_elab.tcl`: `AFRA_ELAB_EXTRA` handling,
`set_elab_time_limit`, `compilation -profile`, `task -create FPV`, the
proofgrid profile, and `MULTIPLE_DRIVEN` reported rather than fatal.
Deliberately NOT added: `-create_related_covers` / `-witness_cover_property`,
which would attach precondition/witness covers to every helper an agent writes.

### The one load-bearing ordering decision

`ft/defines.sv` is a **header**, and it is the **first analyzed file**. The
SERV RTL does not include it, and `serv_top.v:25`, `serv_rf_top.v:46` and
`serv_debug.v:16` guard the entire RVFI port list behind
`` `ifdef RISCV_FORMAL ``. Analyze the header later and the core elaborates
*without* its rvfi outputs, and `ft/wrapper.sv`'s `` `RVFI_CONN `` names ports
that do not exist. `defines.sv` carries its own `` `ifndef DEFINES_SV `` guard,
so the `` `include "defines.sv" `` that every `sva/` and `ft/` file does is
then inert.

This assumes macros defined in one file of an `analyze` call are visible to the
next, which is the same assumption `tasks/l15_l2_mshr_onehot/lists/tc_elab.files`
already documents and relies on ("the RTL comes first because it carries the
`` `include `` of l2.tmp.h / l15.tmp.h whose macros the checker and the FT then
use"). Slang confirms it locally under `--single-unit`.

### Reset polarity

`reset == 1'b1`, not `reset_n == 1'b0`. `ft/tb.sv` takes `reset` as a top-level
input and `ft/wrapper.sv` wires it straight to SERV's active-high `i_rst`;
`ric3.toml` records `reset = "reset"` and the source's `DERIVATION.json` calls
the semantics a "concrete fminit sequence 1,0". Jasper's
`reset -expression ... -max_iterations 100` with `set_cumulative_reset on`
settles a superset of that one-cycle state, which is sound: every
reset-assigned flop in SERV takes a constant under reset, so iterating does not
narrow the set, and everything not reset-assigned stays free either way.

The polarity is written in **two** places — `lists/tc_elab.tcl` and
`lists/reset_modes.tcl` (`::rm_reset_expr`, which `v5/cex.tcl:ENTER_FRA_KEEP`
re-applies after the cut). They must agree. Getting the second one wrong does
not fail loudly.

## Scrubbed: nothing, and why

Unlike the OpenPiton ports there was nothing to remove. The package contains no
`FLS_EVALUATION` include hook, no reference to a golden environment, no helper
web and no worked solution. `DERIVATION.json` states it outright: *"No helper
assertions or assumptions are present in the canonical task."* The only
in-package comments are upstream riscv-formal copyright headers, the
`// DO NOT EDIT -- auto-generated from riscv-formal/insns/generate.py` banner,
and SERV's own code comments. None of them names a proof, a helper set or an
environment an agent could go looking for.

`engine/ric3.toml` and `DERIVATION.json` were not copied. That is a *drop*, not
a scrub: neither is part of the design, and everything in them that is a fact
about the task is recorded above.

## Dropped hash gates

The source's `DERIVATION.json` is a SHA-256 manifest — a
`source_sha256`/`destination_sha256` pair per file — and this repo does not
carry content hashes or hash-based validation gates. It was not copied.
Everything in it that is not a hash is recorded here: the top, the clock, the
reset and its semantics, the two target assertions, the upstream commits, and
the note that the canonical task ships no helpers. The source file remains in
the source tree if the manifest is ever wanted.

## DESIGN_KEEP: one register, and cutting it would be a FALSE PASS

    design_keep: ["rvfi_order_loopback"]

`ft/tb.sv` holds one register:

    reg rvfi_order_loopback;
    always @(posedge clock) begin
        if (reset) rvfi_order_loopback <= 0;
        else if (rvfi_valid && rvfi_order == {64{1'b1}}) rvfi_order_loopback <= 1;
    end
    always_comb assume (!(rvfi_order_loopback && check));

This is the CIll artifact's own addition, and its README says why: riscv-formal
was written for **bounded** checking, so `rvfi_order` wrapping past 64 bits can
invalidate a check that is run unbounded. The assumption disables `check` once
a wrap has been seen.

Under `ENTER_FRA_KEEP` every register not matched by a keep pattern is
`stopat -reset` and starts arbitrary. With an empty keep list
`rvfi_order_loopback` starts arbitrary, and on the branch where it starts **1**
the assumption forces `check == 0` for the whole trace. Every target in this
package is guarded by `check`, so all of them would be **vacuously proven**.

That is the dangerous direction. A cut instrument normally costs a spurious
counterexample — visible, annoying, correctable. Here it costs a spurious
PASS, which nothing downstream would flag. It is the same "preserve the
instrument, cut the design" rule as `_CHECKER_KEEP` and pmesh's `ref_*`
pointers, applied to an assumption's state rather than an assertion's.

`rvfi_order_loopback` is reset-assigned, so the pattern cannot match zero and
cannot trip `cex.tcl`'s "design keep pattern matched nothing" FAIL. Expect
exactly **1** hit.

Nothing else is kept, deliberately:

- **`rvfi_insn_check` has no registers at all.** It is wires and two immediate
  assertions; `rvfi_insn_addi` is pure combinational spec. There is no
  instrument state for the two targets to lose.
- **`ft/wrapper.sv`'s four `(* keep *) reg`s** (`ibus_rdt`, `ibus_ack`,
  `dbus_rdt`, `dbus_ack`) are the riscv-formal idiom for a free memory
  response: declared `reg`, never assigned, so already free every cycle.
  `stopat -reset` on them is a no-op. Their two Wishbone assumptions are
  combinational over them and over `cyc`, and hold no state.
- **All ~210 SERV registers stay cut.** That is the experiment.

## Known blocker, not fixable inside this package

`taskdefs.derive_targets` will report both targets as
**"not located in the mounted sources"**, and `v6_dataset/model.py:target_text`
renders that straight into the model prompt.

The cause is `taskdefs.TARGET_PATTERN = "assert property"`. `derive_targets`
accepts a label only on a line that also contains that string. Upstream
riscv-formal writes its checks as **immediate** assertions inside a clocked
always block:

    always @(posedge clock) begin
        if (!reset && check && spec_valid) begin
            if (`rvformal_addr_valid(rvfi_pc_rdata) && !mem_access_fault) begin
                if (!spec_trap) begin
                    o_rd_wdata_match: assert(spec_rd_wdata == rvfi_rd_wdata);
                    o_pc_wdata_match: assert(`rvformal_addr_eq(spec_pc_wdata, rvfi_pc_wdata));
                end
            end
        end
    end

so the label line has no `assert property` and the scan misses it. This is a
property of **all eight** SERV packages.

It was NOT fixed by rewriting the assertions. The rewrite is expressible — one
`wire` for the nested conditions and two `assert property (@(posedge clock)
... |-> ...)` — but these packages exist to be comparable against the CIll
paper's numbers on the same checks, and a re-expressed assertion is no longer
the same check. The honest fix is one word in `taskdefs.py`
(`TARGET_PATTERN`, or a per-task pattern), which the porting brief forbids
touching.

**Consequence while it stands:** the model prompt tells the agent the target is
not in the sources. It is — `sva/rvfi_insn_check.sv`, lines 67 and 68. Nothing
else is affected: `v5/cex.tcl` resolves targets from Jasper's own property
list via `LABEL_INDEX`, which keys on the last dot-separated component and sees
immediate assertions fine.

The second blocker recorded for `openpiton_pmesh_order` applies here too:
`v5/round.py` emits `v4pre_round.TARGETS` (the hardcoded the internal reference task pair)
instead of `taskdefs.TASKS[task]["target_labels"]`, so a round on any task
outside the internal reference task family resolves no target.

## Correction 2026-08-19 — `default_nettype` switched, and rtl/ is no longer byte-identical

The claim above that `rtl/`, `sva/` and `ft/` are byte-identical to the source
**no longer holds**, and this records exactly how far it is broken.

`` `default_nettype none `` was switched to `` `default_nettype wire ``
everywhere it appeared in this package: 18 files across `rtl/`, `sva/` and
`ft/`. Nothing else changed — no port declaration, no expression, no property
text, no module boundary.

**Why.** Upstream riscv-formal declares ANSI ports as bare `input rvfi_valid,`
with no net type, under `default_nettype none`. That is non-conforming per
IEEE 1800. yosys and slang infer a wire and proceed; Verific refuses, and
Jasper elaboration died with 19 errors before any proof ran — while
`elab_local.py` passed the package cleanly, because slang is one of the lenient
tools.

**Why this and not something else.** Two alternatives were tried and rejected:

  * `set_message -warning VERI-1906` took the error count 19 -> 2 but only
    stopped Verific *complaining* the port had no type; it did not give it one,
    so `assign spec_valid = rvfi_valid && ...` failed instead. A suppressed
    error over a half-elaborated design is worse than a clean failure.
  * Adding `wire` to each port would edit the declarations themselves, which is
    a larger change to a generated file than changing one directive.

`default_nettype` is a LINT STRICTNESS directive, not a semantic one. The ports
beneath it rely on net inference either way; switching it makes Verific infer
what yosys and slang already infer. The property being checked is unchanged,
which is what matters for comparing against CIll's published numbers on these
same checks.

**Provenance impact.** `rtl/` is gitignored under this repository's convention
(upstream, byte-identical, recorded here rather than vendored). That convention
now has one exception on this package, and anyone reconstructing `rtl/` from
upstream must apply the same substitution or Jasper will not elaborate it.
